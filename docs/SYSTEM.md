# SYSTEM.md — JHCSC Smart Panic Button System

Generated by read-only analysis on 2026-10-22. Items marked "(unverified)" were not confirmed by running them.
Hardware/device specifics (IPs, pins, SIM800L runbook) live in `AGENTS.md` — not duplicated here.

## 1. Overview
- Campus emergency system for JHCSC: ESP32 panic buttons (Library, Gym, Engineering bldg) post alerts to a Laravel server; SMS fallback via SIM800L when WiFi/server is down.
- Users: **DRRMO** (disaster response office; acknowledges, dispatches, resolves) and **Clinic** (sees medical/critical alerts, treats patients). Witnesses use the physical buttons.
- Alert categories: `Critical Emergency`, `Medical Emergency`, `Public Safety Emergency`.

## 2. Tech stack
- PHP ^8.3, Laravel ^13.8 (installed 13.22.0), Laravel Reverb (WebSockets), Sanctum (barely used), Tinker.
- Tests: Pest ^4.7 + pest-plugin-laravel; formatter: Laravel Pint; dev: Boost, Pail, Pao.
- Frontend: Blade views, Alpine.js (CDN, pinned 3.15.0), Tailwind v4 built by Vite (`resources/css/app.css` holds theme tokens + shared classes `nav-link`, `ui-card`, `ui-input`, `ui-btn`, `app-*`; run `npm run build` after view changes), Leaflet 1.9.4 (unpkg, `resources/views/ndrrmo/map.blade.php`), laravel-echo + pusher-js (`resources/js/echo.js`).
- DB: MySQL per `.env`/`.env.example` (DB name `smartbutton`), hosted in rootless podman pod `mysql-stack` (`mysql-server` + phpMyAdmin; restart with `podman pod restart mysql-stack` if port 3306 disappears); SQLite in-memory for tests; README says SQLite locally (outdated). Sessions/cache/queue use `database` driver.
- Firmware: Arduino C++ for ESP32 (`arduino-cli`, FQBN `esp32:esp32:esp32`) with SIM800L GSM modem.
- Hosting: no deploy config in repo; runs on a LAN host `0.0.0.0:8000` via `php artisan serve` (see AGENTS.md). `.agents/skills/deploying-laravel-cloud` exists but no Laravel Cloud config (unverified use).

## 4. How to run
- Setup: `composer install && npm install && cp .env.example .env && php artisan key:generate`, configure DB, then `php artisan migrate --force && php artisan db:seed`. Or `composer run setup`.
- Dev (server + queue + vite): `composer run dev` (serves `php artisan serve --host=0.0.0.0`, port 8000).
- Reverb (optional): `php artisan reverb:start` (not in `composer run dev`).
- Test: `composer run test` or `php artisan test` (verified 2026-10-22: 63 passed, 262 assertions).
- Format: `vendor/bin/pint`.
- Build assets: `npm run build`.
- Simulate hardware: `php artisan device:simulate --list | --device=GYM-001 --category="Critical Emergency" | --all | --new`; or browse `/simulator`.
- Firmware: compile/upload/monitor commands in `AGENTS.md` §4.
- Deploy: no scripted deploy. `composer run save` does `git add . && commit && git push origin master` (branch is `main` — broken; avoid).

## 5. Main workflows
**A. Alert from device (online)**
1. Button press → ESP32 (`Library.ino` `triggerAlarm` → `sendPanicAlert`) POSTs JSON to `/api/emergency`.
2. `Api/DeviceController::emergency` validates, finds `Device` by `device_code` (404 if unknown, 409 if not `active`), updates `last_seen`, ignores a same device/type/`need_clinic` repeat within 30 s (200 + `duplicate:true`), creates `Incident` (`Pending`; `need_clinic` defaults true for Critical/Medical, false otherwise), `Notification` rows (DRRMO always; Clinic if Critical, or Medical with `need_clinic`), then `broadcast(new EmergencyReported)`.
3. Dashboards pick it up: Echo listener `window.Echo.channel('emergencies')` and 1.5 s polling of `/ndrrmo/stats-json` or `/clinic/stats-json` (in `layouts/ndrrmo.blade.php`, `layouts/clinic.blade.php`) → modal + siren.
4. Device polls `GET /api/device/status` every 1.5 s while alarming; stops buzzer when `drrmo_responded` true or `has_pending` false (`checkAcknowledgeStatus`).

**B. Offline failover** (SIM800L currently unreliable: no signal/registration and power restarts as of 2026-10-22; local siren now auto-stops after 60 s in firmware, not yet uploaded): if WiFi down or HTTP not 2xx, `Library.ino` sends SMS via SIM800L (`sendEmergencySMSAlert`) to 3 numbers. Format: `JHCSC PANIC ALERT (OFFLINE)! Device: … Category: …`. `/api/sms-webhook` expects `EMERGENCY: <DEVICE> - <CATEGORY>` — **does not match the firmware's SMS text**; nothing in repo calls the webhook (needs external SMS gateway, unverified).

**C. Medical flow**: Medical button → device listens 5 s for side buttons GPIO 32 (clinic YES) / 33 (NO), default YES → sends `need_clinic`. Only `Library.ino` has `need_clinic`; Gym/E_building don't (server defaults `true`).

**D. Incident lifecycle** (`Incident.status`): `Pending → Acknowledged → Responding → Resolved`.
- DRRMO: `NdrrmoController::{acknowledgeIncident, acknowledgeAll, dispatchIncident, onSceneIncident, resolveIncident, notifyClinic, bulkDeleteAlerts}` via `/ndrrmo/...`.
- Clinic: same actions in `ClinicController` via `/clinic/...` (404 unless clinic-relevant), plus `destroyAlert`.
- Clinic involvement is decided by `Incident::involvesClinic()` (Critical, or Medical with `need_clinic`, or an existing Clinic notification). Each action updates timestamps (`acknowledged_at`, `dispatched_at`, `arrived_at`, `resolved_at`), writes `Notification` rows, and broadcasts `EmergencyReported` `->toOthers()`.
- Resolve accepts `resolution_type` (`Resolved|False Alarm|Drill`) and patient/triage fields.
- Public API also exposes acknowledge/dispatch/resolve (`routes/api.php`) with **no auth**.

**E. Reports/export**: `reports` and `exportExcel` (tab-separated `.xls` stream) in both dashboard controllers; `Incident` scopes `realEmergencies/falseAlarms/drills`.

**F. Device management** (DRRMO): CRUD in `NdrrmoController::{devices,storeDevice,updateDevice,destroyDevice}`; online = `active` and `last_seen` within 5 min (`Device::getIsOnlineAttribute`). Map: `ndrrmo/map.blade.php` (Leaflet).

**G. Auth**: `/login` (throttle 5/min) → redirect by role (`AuthController::authenticate`); only `status=active` users can log in. Register is **not routed**.

## 6. Data
Tables (`database/migrations/`):
- `users`: fullname, username (unique), password, role (`DRRMO`|`Clinic`), status, remember_token.
- `devices`: device_code (unique), building, floor, room, latitude, longitude, status (`active|inactive|maintenance`), last_seen.
- `incidents`: device_id (FK cascade), emergency_type, need_clinic (bool), reported_at, status, remarks, resolved_at, responder_name/contact, eta_minutes, dispatch_notes, resolution_type, false_alarm_reason, patient_name, patient_id_number, triage_level, treatment_summary, disposition, acknowledged_at, dispatched_at, arrived_at.
- `notifications` (custom model, **name clashes with Laravel's notifications concept**): incident_id (FK cascade), recipient (`DRRMO|Clinic`), channel (`Dashboard|SMS Backup`), status (free text), sent_at.
- `patient_records` (model unused), `activity_logs` (model unused; `down()` drops wrong table `audit_logs`), plus `sessions`, `cache`, `jobs`.
- Seed data: users `gquiling` (DRRMO), `apatigayon` (Clinic); devices GYM-001, ENG-001, LIB-001 (`database/seeders/`).
- `database.sql` is a hand-maintained dump (stale; different DB name).

HTTP API (`routes/api.php`, prefix `/api`, all unauthenticated except `/user`):
- `POST /emergency`, `GET /device/status`, `POST /incidents/{id}/acknowledge|dispatch|resolve`, `POST /sms-webhook`.
Internal JSON: `GET /ndrrmo/stats-json`, `GET /clinic/stats-json`.
External services: none server-side (SMS is sent by the device's SIM800L on Smart/TNT). CDNs: jsdelivr (Alpine), unpkg (Leaflet), Bunny fonts (via Vite).

## 8. Conventions
- Laravel 13 skeleton: thin-ish controllers, validation inline via `$request->validate()`, Eloquent scopes for query reuse, constants on `Incident` for types/triage/resolution.
- Status strings are Title Case literals (`'Pending'`, `'Acknowledged'`, `'Responding'`, `'Resolved'`) repeated in code, not constants/enums.
- Action endpoints return JSON if `wantsJson()` else redirect-back with flash `success`.
- Role-based route groups: `['auth','role:X']` with `prefix` + `name` (`ndrrmo.*`, `clinic.*`). URL/class name `ndrrmo`/`Ndrrmo` is legacy; the role is now `DRRMO`.
- Tests: Pest feature tests with in-memory SQLite (`tests/Feature`).
- Views: Blade with large inline `<script>` blocks, vanilla `fetch` + CSRF; Tailwind utility classes.
- Pint is installed (default Laravel preset assumed); formatting in controllers is inconsistent (unverified that Pint is run).

## 9. Known issues
**Security**
- `AGENTS.md`, `README.md`, `database/seeders/AdminUserSeeder.php`, and all `.ino` files contain **plaintext credentials** (WiFi password, default user passwords, phone numbers) committed to git.
- `/api/*` has no authentication: anyone on the network can create alerts (`/api/emergency`) or acknowledge/dispatch/resolve any incident; `/api/sms-webhook` is unauthenticated and spoofable. Firmware uses plain HTTP.
- `/simulator*` routes in `routes/web.php` are unauthenticated and can create devices, trigger alerts across all devices, and resolve all active alerts.
- `AdminUserSeeder` password reset each seed (`updateOrCreate` keyed on `role`) — re-seeding overwrites any changed password.
- `.env` has `APP_DEBUG` per template `true`; set false in production (value in `.env` not inspected).
- Broadcast channel `emergencies` is public; payload includes full incident + device.
- Clinic `ClinicController::bulkDeleteAlerts`/DRRMO `bulkDeleteAlerts` hard-delete incidents (no audit; `ActivityLog` unused).

**Bugs / fragile**
- Layouts now call `window.Echo?.channel(...)` (guarded) but only `@vite` the CSS, not `resources/js/app.js`, so Echo is never set up; real-time depends on 1.5 s polling.
- Reverb env vars missing and `BROADCAST_CONNECTION=log`; `EmergencyReported` is broadcast but not delivered anywhere.
- `Api/DeviceController::smsWebhook` format mismatch with firmware SMS; doesn't set `need_clinic`/`reported_at` and always notifies Clinic for Medical regardless; uses `->toOthers()` on a non-socket request.
- `Api/DeviceController::dispatch/resolve/acknowledge` don't set `acknowledged_at/dispatched_at`, don't create Notifications or broadcast — inconsistent with dashboard actions.
- `GET /api/device/status` marks `drrmo_responded` from the latest incident only; firmware does naive substring JSON parsing.
- `SimulatorController::resetAlerts` Clinic notification skips the `need_clinic` check used elsewhere.
- `ActivityLog` migration `down()` drops `audit_logs`.
- `composer run save` pushes to `master`; repo branch is `main`.

**Duplication**
- `NdrrmoController` and `ClinicController` duplicate acknowledge/dispatch/onScene/resolve/bulkDelete/export logic; the "notify Clinic if critical/medical" block is copy-pasted ~10 times.
- `layouts/ndrrmo.blade.php` vs `layouts/clinic.blade.php` duplicate modal/siren/polling JS (~1000 lines each).
- Three near-identical `.ino` files (Gym/E_building lack Library's SIM800L init, medical flow, serial commands — unverified diff scope).
- `reports()` builds each stat twice (lowercase + capitalised keys).
- `Notification` creation repeated inline instead of a service/action.

**Outdated / dead**
- README: says SQLite and "Laravel Mix" — actual is MySQL + Vite; lists default credentials.
- `AuthController::register`/`showRegisterForm` + `register.blade.php` unrouted; `DeviceController` (root), `DashboardController`, `IncidentController`, `PatientRecord`, `ActivityLog` unused.
- `ndrrmo`-named files/routes after rename to DRRMO.
- `composer outdated`: laravel/framework 13.22.0→13.38.0, reverb 1.11→1.12, pint, boost; Pest 4→5 available.
- `database.sql` out of date vs migrations (unverified column parity).
- Alpine, Leaflet and Google Fonts still load from CDNs (dashboard host needs internet).
